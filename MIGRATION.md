# Migration to POV Staff 5

This is a breaking replacement, as requested. There is no legacy firmware mode or compatibility scheduler.

- **Networking:** AP is the default on every factory-new configuration, independent of orientation. Client mode is explicitly saved in the dashboard and applied only at boot. Bad credentials or a missing home network enable AP fallback. Saving settings does not disconnect the current session.
- **Loading sequences:** use the dashboard on port 80. The old port-8080 file manager and uploader-only startup loop are gone. Each upload is staged, validated and atomically renamed; interruption leaves the previous file intact.
- **Sequence preview in installed 5.1.1:** inspect uploaded BMPs in the browser as a spinning light trail, stationary animated LEDs or full-rotation exposure. The model follows the documented two identical 72-pixel, 50 cm arms and 41 cm unlit central grip; pixel 0 is inner and pixel 71 is at each tip. Preview selection is independent of real playback. The browser caches up to 12 decoded BMPs and renders locally; no generated video files or preview assets are added to LittleFS.
- **Playback:** only 72-pixel-wide uncompressed 24-bit BMP images are accepted. Rows play in visual top-to-bottom order. Valid BMPs form a filename-sorted playlist, with one selectable interval (zero holds the current image). `imagelist.txt` is ignored. Existing BMPs meeting those limits are automatically discovered; other old files are not executed or served.
- **Runtime:** Auto, POV, LED Test, Walking Stick, Sword, Flashlight, Solid, Breathing, Rainbow, Chase, Battery, Idle and Off share one cooperative loop. Manual selection locks the mode; unlock restores automatic orientation/motion behavior.
- **Brightness:** defaults are lower, all frame output passes through gamma/brightness/current scaling, and a critical or invalid battery reading blocks normal output. Uploads/OTA intentionally hold the main LEDs black. Missing/corrupt storage also keeps the main strips black while the dashboard remains available.
- **USB power introduced in 5.0.4:** a positive hardware CDC USB-host detection plus a 4.45–5.50 V supply reading is classified as USB power. This addresses the 4.71–4.72 V USB bench reading that kept version 5.0.3 black. Detected USB hosts impose brightness 16/255 and estimated LED-current 500 mA caps even with a battery-range reading. USB supply telemetry has no battery percentage. Battery cutoff/recovery remain 3.20/3.35 V. Bench telemetry and dashboard checks passed with the serial monitor closed; visible LED operation and real electrical current remain to be checked.
- **IMU:** retains the small local driver with checked burst reads, block-data-update, register verification, reconnect handling, and a ±2000 dps gyro range. No legacy ±500 dps option is included.
- **Filesystem:** LittleFS is retained for local flash storage. Failed mounts never format automatically. Initialize/reset storage explicitly from the dashboard, after retrieving any files you want to preserve by your prior workflow. The 5.1 preview releases add read access to validated BMP contents for preview alongside sequence metadata; arbitrary old filesystem contents remain unavailable.
- **Access and updates:** versions 5.0.3 and 5.0.4 use an open staff AP, a dashboard without a login, and password-free ArduinoOTA. Browser application OTA is available from either network. First install uses USB to establish the OTA partition layout. Filesystem OTA is disabled. Anyone who can reach the staff can control it and upload files or firmware.
- **Dependencies:** removed `pov-esp32` and `ESPxWebFlMgr`; no internal HTTP headers. The current ESP32 Arduino core is used with a pinned reproducible CLI build and Arduino IDE compatibility.

Lighting mode, selected image, duration, color and brightness are runtime controls and reset on boot. Wi-Fi configuration is the only dashboard preference persisted in NVS. Home Wi-Fi credentials remain saved; removing staff access passwords does not remove the home-network password or change the saved client choice. Storage formatting does not clear Wi-Fi settings.

If client mode prevents access at home, wait ten seconds and join the fallback AP. The client radio stops scanning once fallback starts, keeping the AP stable until the next boot. Select AP in Settings and power cycle to make AP the persistent choice. mDNS support varies across phones and LANs; the numerical IP is the reliable fallback.
